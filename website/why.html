Why

Why a JD2-shaped, Linux-native download manager — and why not just…

Because JDownloader2 is good, and closed

JDownloader2 earned its user base: the grabber that turns a pile of links into tickable packages, the pack-by-folder rules, the way the same archive appears once on every mirror and the same page is never downloaded twice by mistake, the tiny toolbars that do exactly half a job each and do it well.

On Windows, the trade is reasonable: pay the Java tax, live in the UI. On Linux the tax is higher — a Java runtime, a second set of permissions, a container that doesn't trust your filesystem — for a program you use every day.

What we didn't want

  • Java. One binary, system libraries, a browser-engine-like client.
  • An updater that silently replaces the running binary from a third-party CDN.
  • A wall of upsell and "paid features" for a download manager.
  • A website that looks generated and doesn't tell you what the program does.

What we kept

  • The two-tab shape (Downloads / Linkgrabber).
  • Packages with a parent path — group by shared folder, not by "best effort" CDN-name heuristics.
  • A packagizer that does the boring part: sort this into that folder, rename that thing, stop after three rules.
  • Features exposed as configuration you can read, not as oracle magic.

What we didn't do

  • No AI features. No "smart" suggestions. No privacy policy generator. No MCP server (for now).
  • No cloud account requirement for anything.
  • No phone-home tracking. There is nothing to phone home with (Rust binary, open source).
  • No ads. No sponsored "fastest mirror" recommendations.

Relationship to Mister Download Manager

ZDownloader3 is a fork of Mister Download Manager by Ahmed Nefzaoui. The fork pivots the project from "the IDM clone" toward "the JD2 clone on Linux", keeps the upstream engine and its guarantees, and collects JDownloader2-shaped behavior from the upstream roadmap.

Upstream's licensing stands; this fork keeps GPL-3.0. Attribution is kept, not buried.
